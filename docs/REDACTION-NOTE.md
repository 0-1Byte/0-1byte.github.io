# 关于「不要在对话/提交信息里粘贴 Key 片段」

## 发生了什么

第一次用探针时，输出里显示了 Key 的前 6 位与末 4 位（`wrk-` 之后的片段）。
这个输出被粘进了对话，随后又被我写进了提交信息 —— 于是这些片段进入了 git 历史。

**这不是完整的 Key，但也不是应该留在历史里的东西。**

## 处理

1. `redact()` 已改为只显示**首 4 位 + 末 2 位**，前缀更短、可还原性更低
2. git 历史中的相关提交信息已清洗
3. `tools/weread_check_secrets.py` 的历史扫描会继续覆盖这类片段

## 建议：重新生成一把 Key

去 <https://weread.qq.com/r/weread-skills> 重新创建，然后删掉旧的。

这是最干净的做法，成本只有一分钟。原因：

- 即使片段不足以直接使用，它仍然标识了「是哪一把 Key」
- 旧 Key 的完整值一直以明文存在本机 `.secrets/key.yaml`
- 轮换一次可以把「曾被记录过」这件事彻底清零

## 以后怎么做

- 探针输出、错误信息、截图 —— 粘之前先看一眼有没有 `wrk-`
- 提交信息里不要带任何 Key 片段
- 想确认 Key 是否正确，用 `python tools/weread_diag.py` 的 A 段：
  它只报告「干净 / 有脏字符」，不打印任何片段
